# Declutter UI

Prioritize the visitor's main task and remove elements that do not help it.

## Assess

Read the page's purpose, audience, brand direction, and existing navigation. Inspect the actual interface before editing.

For each visible element, ask what task, information, orientation, or reassurance it provides. Look for duplicated actions, filler copy, unnecessary containers, and sections that delay the main content.

## Decisions

- Dashboards and member tools often benefit from opening directly on useful content.
- Marketing and editorial pages may need introduction, context, or a hero; decide from their purpose.
- Remove duplicate controls only when findability and responsive navigation remain adequate.
- Keep skip-to-content links, useful section anchors, tables of contents, form navigation, legal links, and other working navigation.
- A same-page link is useful when it saves effort or improves orientation. Remove it when it adds no value.
- Keep help text that explains constraints, errors, consequences, or unfamiliar terms.
- Keep the established style and required functionality.

## Execute and verify

When cleanup is requested, make small reversible changes within scope without adding a second approval step. Ask only if removing a function or business requirement needs a decision.

Check phone and desktop layouts, navigation, keyboard focus, and the main user task. Describe what was removed and why. Record a project-wide design rule only when requested or clearly intended.

Accessibility reference: [W3C Bypass Blocks](https://www.w3.org/WAI/WCAG22/Understanding/bypass-blocks.html).
