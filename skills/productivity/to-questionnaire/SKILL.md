# To Questionnaire

Prepare a short questionnaire that gets the information needed to make a decision.

## Context

Use the conversation and project to identify the recipient, what they know, and which decisions depend on their answers. Ask the user only for genuinely missing context.

## Document

Write in the recipient's language with:

1. Purpose and the decisions the answers will inform.
2. Enough context to answer without reading the chat.
3. Questions ordered by importance, grouped only when useful.
4. A response format, space for answers, and a short reason where a question could be misunderstood.
5. An invitation to flag uncertainty and add missing concerns.

Use one idea per question. Avoid implementation jargon for nontechnical recipients, invented deadlines, and asking for facts already available in the project.

Deliver the requested format or a shareable Markdown document in the project's docs location. Do not send it to the recipient unless the user explicitly requested sending.

## When answers return

Reconcile them with existing requirements, update the spec or glossary as appropriate, flag conflicts, and continue the authorized work.
